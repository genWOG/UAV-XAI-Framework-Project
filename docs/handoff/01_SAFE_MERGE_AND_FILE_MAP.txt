3. КАК ОБЪЕДИНЯТЬ ФАЙЛЫ, ЧТОБЫ НЕ СЛОМАТЬ СОВМЕСТИМОСТЬ
=======================================================

Группа A — конфигурация explainers
----------------------------------

config/yolo_explanation_resolution960_kernel.yaml → factory.py → lime_image.py / shap_image.py.

- При конфликте в factory.py объединяйте словари аргументов, не заменяйте их целиком более старой версией.
- Если поле есть в YAML, factory должна передать его в правильный конструктор, а конструктор — проверить значение и использовать его.
- explanation_image_size относится к LIME и SHAP; algorithm — к SHAP.
- algorithm: kernel сохраняет протестированный Kernel SHAP; partition остаётся экспериментальным вариантом.
- Отсутствие explanation_image_size должно сохранять прежний путь с исходным размером изображения.

Группа B — порог предсказания
-----------------------------

model.prediction_confidence_threshold → predictor.py → тест test_prediction_confidence_threshold.py.

- Значение опциональное. Если его нет, должен сохраняться прежний режим.
- Низкий порог, например 0.001, нужен в бенчмарках, где требуется выбрать цель с низкой исходной confidence. Он увеличивает число кандидатов и сам по себе не улучшает модель.
- Не меняйте глобальный default на 0.001 для всех сценариев без отдельного решения: это настройка профиля эксперимента, а не доказанное универсальное значение для эксплуатации.

Группа C — результат pipeline
-----------------------------

runner.py должен сохранять основные метрики и metadata, не меняя смысл уже существующих полей. Удобный минимальный smoke-check — убедиться, что в result.json есть explanations.<method>, runtime_ms, metrics.deletion_auc, metrics.insertion_auc и metadata соответствующего метода.

Что нельзя делать при merge
---------------------------

- Не копировать всю папку src/ поверх другой ветки.
- Не cherry-pick'ать только factory.py или только один explainer без связанного теста и второго конца интерфейса.
- Не заменять config/yolo_multi_method_one_image_fast.yaml новым профилем 960 px: это разные профили для разных сценариев.
- Не добавлять в коммит папки results/, временные конфиги бенчмарков, виртуальное окружение или веса модели, если это отдельно не предусмотрено правилами репозитория.
- Не выполнять git reset --hard, git push --force и не перезаписывать main.
